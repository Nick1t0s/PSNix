# 13 — Только для ПК

> Автоматические установки, нужные только на стационарном ПК:
> экран DeepCool AK620 Digital, фикс доступа к Docker при поднятом Nekoray TUN
> и графический планшет XP-Pen Deco 01 V3 под Hyprland, яркость мониторов
> через DDC/CI, переключение столов в пределах монитора и блокировка экрана
> с гашением вертикального монитора.
> (OpenRGB — отдельно, см. «OpenRGB (вручную).md».)

---

## Требования

- Ubuntu / Debian / Linux Mint
- Права `sudo`

---

## Часть 1 — DeepCool AK620 Digital

> Неофициальный драйвер [`deepcool-digital-linux`](https://github.com/Nortank12/deepcool-digital-linux):
> температура CPU на экране кулера. Кулер должен быть подключён по USB к материнской плате.

### 1.1 Бинарник и проверка

```bash
wget https://github.com/Nortank12/deepcool-digital-linux/releases/latest/download/deepcool-digital-linux
chmod +x deepcool-digital-linux
sudo ./deepcool-digital-linux --list     # должен быть виден "AK620 DIGITAL"
sudo ./deepcool-digital-linux            # тестовый запуск, Ctrl+C — остановить
```

### 1.2 udev-правило (доступ к hidraw)

```bash
echo 'SUBSYSTEM=="hidraw", ATTRS{idVendor}=="3633", MODE="0666"' | sudo tee /etc/udev/rules.d/99-deepcool-digital.rules
sudo udevadm control --reload-rules && sudo udevadm trigger
```

### 1.3 Автозапуск через systemd

```bash
sudo cp ./deepcool-digital-linux /usr/sbin/
sudo tee /etc/systemd/system/deepcool-digital.service >/dev/null <<'EOF'
[Unit]
Description=DeepCool Digital

[Service]
ExecStart=/usr/sbin/deepcool-digital-linux
Restart=on-failure
RestartSec=5s

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload
sudo systemctl enable --now deepcool-digital
```

Проверка: `systemctl status deepcool-digital --no-pager` (active (running)),
логи: `sudo journalctl -u deepcool-digital -n 50`.

### Параметры запуска

```
sudo deepcool-digital-linux -m <MODE>   # режим отображения
sudo deepcool-digital-linux -f          # температура в °F
sudo deepcool-digital-linux -a          # сигнал при перегреве
sudo deepcool-digital-linux -u <MS>     # интервал обновления (по умолчанию 1000)
sudo deepcool-digital-linux -l          # список устройств
```

## Часть 2 — fix-docker-vpn

> Скрипт и systemd-сервис, который держит Docker-контейнеры доступными,
> пока поднят туннель `neko-tun` от Nekoray. Настроен под проводную сеть ПК `enp4s0`
> (на ноутбуке интерфейс другой — адаптировать).

### 2.1 Скрипт

```bash
sudo tee /usr/local/sbin/fix-docker-vpn.sh >/dev/null <<'EOF'
#!/bin/bash
PHYS=enp4s0; TABLE=200; MARK=0x1; TUN=neko-tun

cleanup() {
  ip rule del pref 100 2>/dev/null
  ip route flush table $TABLE 2>/dev/null
  iptables -t mangle -D PREROUTING -i "$PHYS"  -j MARK --set-mark $MARK 2>/dev/null
  iptables -t mangle -D PREROUTING -i br+     -m conntrack --ctstate ESTABLISHED,RELATED -j MARK --set-mark $MARK 2>/dev/null
  iptables -t mangle -D PREROUTING -i docker0 -m conntrack --ctstate ESTABLISHED,RELATED -j MARK --set-mark $MARK 2>/dev/null
}

apply() {
  if ! ip link show "$TUN" >/dev/null 2>&1; then cleanup; return 0; fi
  GW=$(ip -4 route show default | awk '/default/{print $3; exit}')
  HOSTIP=$(ip -4 -o addr show "$PHYS" | awk '{print $4}' | cut -d/ -f1 | head -1)
  [ -z "$GW" ] || [ -z "$HOSTIP" ] && return 0
  cleanup
  ip -4 -o route show | awk '/dev (docker0|br-)/{print $1, $3}' | \
    while read net dev; do ip route add "$net" dev "$dev" table $TABLE 2>/dev/null; done
  ip route add default via "$GW" dev "$PHYS" table $TABLE 2>/dev/null
  ip route add local "$HOSTIP"/32 dev lo table $TABLE 2>/dev/null
  iptables -t mangle -I PREROUTING -i "$PHYS"  -j MARK --set-mark $MARK
  iptables -t mangle -I PREROUTING -i br+     -m conntrack --ctstate ESTABLISHED,RELATED -j MARK --set-mark $MARK
  iptables -t mangle -I PREROUTING -i docker0 -m conntrack --ctstate ESTABLISHED,RELATED -j MARK --set-mark $MARK
  ip rule add fwmark $MARK/0xffffffff lookup $TABLE pref 100
  logger -t fix-docker-vpn "applied (tun up)"
}

apply
ip monitor link | while read -r _; do
  sleep 0.3; apply
done
EOF
sudo chmod +x /usr/local/sbin/fix-docker-vpn.sh
```

### 2.2 systemd-сервис и запуск

```bash
sudo tee /etc/systemd/system/fix-docker-vpn.service >/dev/null <<'EOF'
[Unit]
Description=Keep Docker reachable while nekoray TUN is up
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
ExecStart=/usr/local/sbin/fix-docker-vpn.sh
Restart=always
RestartSec=2

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload
sudo systemctl enable --now fix-docker-vpn.service
systemctl status fix-docker-vpn.service --no-pager
```

### Ручная очистка (снести правило вручную)

```bash

GW=$(ip -4 route show default | awk '/default/{print $3; exit}')
HOSTIP=$(ip -4 -o addr show "$PHYS" | awk '{print $4}' | cut -d/ -f1 | head -1)

sudo ip rule del pref 100 2>/dev/null
sudo ip route flush table $TABLE 2>/dev/null
sudo iptables -t mangle -D PREROUTING -i "$PHYS"  -j MARK --set-mark 0x1 2>/dev/null
sudo iptables -t mangle -D PREROUTING -i br+     -m conntrack --ctstate ESTABLISHED,RELATED -j MARK --set-mark 0x1 2>/dev/null
sudo iptables -t mangle -D PREROUTING -i docker0 -m conntrack --ctstate ESTABLISHED,RELATED -j MARK --set-mark 0x1 2>/dev/null

ip -4 -o route show | awk '/dev (docker0|br-)/{print $1, $3}' | \
  while read net dev; do sudo ip route add "$net" dev "$dev" table $TABLE 2>/dev/null; done
sudo ip route add default via "$GW" dev "$PHYS" table $TABLE
sudo ip route add local "$HOSTIP"/32 dev lo table $TABLE

sudo iptables -t mangle -I PREROUTING -i "$PHYS"  -j MARK --set-mark 0x1
sudo iptables -t mangle -I PREROUTING -i br+     -m conntrack --ctstate ESTABLISHED,RELATED -j MARK --set-mark 0x1
sudo iptables -t mangle -I PREROUTING -i docker0 -m conntrack --ctstate ESTABLISHED,RELATED -j MARK --set-mark 0x1
sudo ip rule add fwmark 0x1/0xffffffff lookup $TABLE pref 100
```

> `sudo ip rule del pref 9003` (правило Nekoray) удаляется всегда отдельно.

## Часть 3 — Графический планшет XP-Pen Deco 01 V3 (Hyprland)

> Перо работает из коробки (планшет виден как `xppen-deco-01-v3-pen` в `hyprctl devices`).
> Эта часть чинит **ориентацию пера на вертикальном мониторе** (`HDMI-A-1`, `transform,1`)
> и переключение мониторов виджетом waybar (`custom/tablet` → `tablet.sh` / `tablet-toggle.sh`).

### 3.1 Суть проблемы

Per-device конфиг в `hyprland.conf`:

```
device {
    name = xppen-deco-01-v3-pen
    output = HDMI-A-1
    transform = 1
}
```

- `output` применялся всегда (это делает сам Hyprland, мимо libinput) — привязка к монитору работала.
- `transform` **молча игнорировался** при любом значении и любом способе применения
  (`hyprctl reload` или передёргивание USB).

Причина (подтверждена по исходникам Hyprland 0.53.3 / libinput 1.31.1 / libwacom 2.18):

1. Hyprland реализует device-`transform` для планшетов через libinput calibration matrix.
2. libinput устанавливает конфиг калибровки планшета только если устройство «дисплейное»
   по libwacom **или** имеет `INPUT_PROP_DIRECT` на evdev-узле.
3. Ядро (hid-generic, у Deco 01 V3 нет родного драйвера hid-uclogic — его нет в ID-таблице)
   не выставляет `INPUT_PROP_DIRECT` (`properties=0` у узла пера).
4. libwacom знает планшет (`/usr/share/libwacom/xp-pen-deco01-v3.tablet`) с пустым
   `IntegratedIn=` → libinput не считает его дисплейным → калибровка не устанавливается →
   `set_matrix()` возвращает UNSUPPORTED, без единого сообщения в лог.

### 3.2 Фикс: override libwacom

Копия системного `.tablet`-файла, но с `IntegratedIn=Display` и `Reversible=false`.
Файл лежит в репо (`pc/configs/libwacom/xp-pen-deco01-v3.tablet`):

> **Имя файла обязано совпадать с системным** (`xp-pen-deco01-v3.tablet`): libwacom
> перекрывает по имени файла; тот же `DeviceMatch` под другим именем даст
> "Duplicate match" и сломает всю базу libwacom.
> `Reversible=false` — иначе libwacom warning «reversible + display impossible»;
> это лишь выключает left_handed-режим пера.

```bash
mkdir -p ~/.config/libwacom
cp -v $HOST/configs/libwacom/xp-pen-deco01-v3.tablet ~/.config/libwacom/xp-pen-deco01-v3.tablet
```

`~/.config/libwacom` — первый по приоритету каталог базы libwacom
(порядок: `~/.config/libwacom` → `/etc/libwacom` → `/usr/share/libwacom`).

### 3.3 Конфиги планшета

```bash
cp -v $HOST/configs/hypr/hyprland.conf                   ~/.config/hypr/hyprland.conf   # device-блок уже внутри
cp -v $HOST/configs/waybar/scripts/tablet.sh             ~/.config/waybar/scripts/
cp -v $HOST/configs/waybar/scripts/tablet-toggle.sh      ~/.config/waybar/scripts/
chmod +x ~/.config/waybar/scripts/tablet-toggle.sh
```

Модуль `custom/tablet` уже подключён в `$HOST/configs/waybar/hyprland-config`.

Важно: в device-блоке **не задавать `transform` вне пары с виджетом** — значение `0`
(и вообще любое > -1) затирает калибровку, отсутствие ключа = «не трогать».

### 3.4 Перезапуск и проверка

Перезапустить **всю сессию Hyprland** (не `hyprctl reload` — базу libwacom libinput
читает один раз при старте). Затем:

1. Клик по виджету планшета в waybar: состояние DP-3 (t=0) ↔ HDMI-A-1 (t=1),
   правятся оба конфига (`~/.config/hypr/hyprland.conf` и репо) + `hyprctl reload`.
2. На вертикальном HDMI: перо вверх → курсор вверх, перо вправо → курсор вправо.

### 3.5 Если ориентация не та

Теперь `transform` реально применяется — меняется одним `hyprctl reload`, **без
передёргивания USB** (reload переигрывает device-конфиги). Наблюдения для вертикального HDMI:

| transform | перо вверх → | перо вправо → | что это |
|---|---|---|---|
| 1 | вверх | вправо | **рабочий** (по матрице калибровки: Sx = 1−Ty, Sy = Tx) |
| 5 | вверх | влево | зеркало 1 по X (проверено: Y верный, X инвертирован) |

Остальные значения (0/2/3/4/6/7) при необходимости перебираются тем же
`hyprctl reload` — все 8 значений образуют полную группу симметрий квадрата,
включая любое зеркало/поворот.

Значение подставляется в device-блок и в `next_t` в `tablet-toggle.sh`.

> Диагностика при желании: `libinput list-devices` (пакет `libinput-tools`),
> `cat /sys/class/input/input*/properties` (у пера было `0` — нет `INPUT_PROP_DIRECT`).

## Часть 4 — Яркость мониторов через DDC/CI (фикс микрофризов)

> Симптом: система периодически заикается каждые ~5–10 сек, особенно заметно
> при записи экрана через OBS. Причина: waybar-модуль `custom/brightness`
> каждые 5 сек запускал `ddcutil getvcp 10` для **обоих** мониторов —
> DDC/CI-транзакции по I²C на NVIDIA занимают десятки–сотни мс и дают
> микрофризы. Постоянный ddcutil-опрос на этой машине **запрещён**.

Схема: значения яркости кэшируются в `~/.cache/waybar-brightness/HPN|AUS`:

- `scripts/brightness.sh` — модуль waybar, **только читает кэш**, обновляется
  по сигналу `SIGRTMIN+7` (`"signal": 7` в `custom/brightness`, без `interval`);
- `scripts/brightness-change.sh +5|-5` — меняет яркость (ddcutil `setvcp`
  только по нажатию/скроллу), пишет кэш и шлёт `pkill -SIGRTMIN+7 -x waybar`;
- хоткеи `hyprland.conf` (`XF86MonBrightnessUp/Down`) и `on-scroll-up/down`
  модуля вызывают `brightness-change.sh`.

Все четыре файла уже лежат в `pc/configs/` (копируются в Шаге 2/3 доки 12).
После ручного копирования перезапустить waybar и засеять кэш:

```bash
systemctl --user restart waybar-hyprland.service
mkdir -p ~/.cache/waybar-brightness
for m in HPN AUS; do
  ddcutil -t -g "$m" getvcp 10 | awk '$2==10 {print $4}' > ~/.cache/waybar-brightness/$m
done
```

Проверка: `~/.config/waybar/scripts/brightness.sh` печатает JSON с текущими
значениями; подождать 15+ сек — `ps -e | grep ddcutil` пуст (опроса нет);
хоткеи яркости работают и обновляют виджет.

> Кэш расходится с реальностью, если яркость менять кнопками на мониторе —
> тогда одно нажатие хоткея перезасеет значения (скрипт при отсутствии кэша
> делает разовый `getvcp`).

## Часть 5 — Переключение столов в пределах монитора

> Столы 1–10 — главный монитор, 11+ — вертикальный. Штатные `workspace -1/+1`
> и `e±1` на границе 10 ↔ 11 перекидывали на другой монитор. Скрипт
> `ws-step` шагает только внутри текущего монитора, на границе ничего не делает.

- `pc/configs/hypr/ws-step.sh` → `~/.local/bin/ws-step` (нужен `jq`);
- в `hyprland.conf` на него переведены `Win+Ctrl+Shift+h/l` и `Win+колесо`.
  Жест тремя пальцами и `Win+1..0` не затронуты.

```bash
install -Dm755 $HOST/configs/hypr/ws-step.sh ~/.local/bin/ws-step
cp -v $HOST/configs/hypr/hyprland.conf ~/.config/hypr/hyprland.conf
hyprctl reload
```

## Часть 6 — Блокировка экрана с двумя мониторами

> Симптом: после блокировки, выключения главного DP-3 кнопкой и разблокировки
> на waybar появлялись столы 12–15, и главный монитор оказывался на одном из них.
> Иногда пропадали обои на hyprlock.
>
> Причина: `lock-screen` отключал HDMI через `monitor HDMI-A-1,disable`, и тот
> пропадал из Hyprland. DP-3 по DisplayPort при выключении кнопкой тоже
> отключается (`Connector DP-3 disconnected` в `hyprland.log`). Мониторов не
> оставалось совсем, и Hyprland подключал виртуальный FALLBACK. Каждому
> подключённому монитору без правила `default:true` он создаёт стол с первым
> свободным номером, а 1–10 заняты DP-3, так что номер всегда 11+. После
> включения DP-3 этот стол доставался ему активным.

Фикс:
- `lock-screen` гасит HDMI через `hyprctl dispatch dpms off HDMI-A-1`, а не
  отключает. Монитор остаётся в Hyprland, и при выключенном DP-3 столы
  временно переезжают на него, а потом возвращаются. Раскладку мониторов
  скрипт больше не трогает. После разблокировки `dpms on` и перезапуск hyprpaper;
- проверка `pidof hyprlock` стоит до `trap`: повторный вызов во время
  блокировки (hypridle `lock_cmd`) не включает HDMI;
- в `hyprland.conf`: `default:true` у стола 1 на DP-3 и у стола 11 на HDMI-A-1;
- в `hypridle.conf`: `after_sleep_cmd = hyprctl dispatch dpms on DP-3`, иначе
  после сна HDMI загорится, пока экран ещё заблокирован.

```bash
install -Dm755 $HOST/configs/hypr/lock-screen.sh ~/.local/bin/lock-screen
cp -v $HOST/configs/hypr/hyprland.conf ~/.config/hypr/hyprland.conf
cp -v $HOST/configs/hypr/hypridle.conf ~/.config/hypr/hypridle.conf
hyprctl reload
pkill -x hypridle; hyprctl dispatch exec hypridle   # hypridle конфиг не перечитывает
```

Проверка: заблокировать, выключить DP-3 кнопкой, подождать ~10 с, включить,
разблокировать. DP-3 на прежнем столе из 1–10, HDMI на 11, на waybar только 1–10.

> Фикс держится на том, что HDMI-монитор (ASUS PA24A) без сигнала остаётся
> подключённым. Если выключать кнопкой и его, мониторов снова не останется.
