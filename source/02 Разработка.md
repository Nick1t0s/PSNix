## Шаг 1 — Git, git-lfs, GitHub CLI

```bash
sudo apt install git git-lfs gh -y
```

- `git-lfs` — большие файлы (бинарники, модели)
- `gh` — репозитории, PR, issues прямо из терминала

Проверка:

```bash
git --version && git lfs version && gh --version
```

Авторизация gh (интерактивно): `gh auth login` → GitHub.com → HTTPS → Login with a web browser.

Если `gh` нет в репозитории:

```bash
(type -p wget >/dev/null || (sudo apt update && sudo apt-get install wget -y)) \
&& sudo mkdir -p -m 755 /etc/apt/keyrings \
&& out=$(mktemp) && wget -nv -O$out https://cli.github.com/keyring/githubcli-archive-keyring.gpg \
&& cat $out | sudo tee /etc/apt/keyrings/githubcli-archive-keyring.gpg > /dev/null \
&& sudo chmod go+r /etc/apt/keyrings/githubcli-archive-keyring.gpg \
&& echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/githubcli-archive-keyring.gpg] https://cli.github.com/packages stable main" | sudo tee /etc/apt/sources.list.d/github-cli.list > /dev/null \
&& sudo apt update && sudo apt install gh -y
```

## Шаг 4 — Node.js и npm

## Шаг 8 — JetBrains Toolbox (без sudo!)

> ⚠️ Toolbox ставится в домашнюю директорию пользователя — не используй `sudo` и не клади в `/opt`.

```bash
wget "https://download.jetbrains.com/toolbox/jetbrains-toolbox-$(curl -fsSL 'https://data.services.jetbrains.com/products/releases?code=TBA&latest=true&type=release' | grep -o '"build":"[^"]*"' | head -n1 | cut -d'"' -f4).tar.gz"
mkdir -p ~/.local/share/JetBrains/Toolbox
rm -rf ~/.local/share/JetBrains/Toolbox/jetbrains-toolbox-*
tar -xzf jetbrains-toolbox-*.tar.gz -C ~/.local/share/JetBrains/Toolbox
~/.local/share/JetBrains/Toolbox/jetbrains-toolbox-*/bin/jetbrains-toolbox
rm -f ~/jetbrains-toolbox-*.tar.gz
```

При первом запуске прими пользовательское соглашение — после этого появится ярлык в меню.

## Шаг 9 — Vim-навигация в PyCharm и CLion

Раскладка «XWin copy» (родитель «Default for XWin»):

- `Alt+H/J/K/L` — курсор влево/вниз/вверх/вправо (стрелки тоже работают)
- `Ctrl+Alt+H/L` — на слово влево/вправо
- Сняты конфликтующие сочетания: `Alt+J` (Select Next Occurrence),
  `Ctrl+Alt+H` (Call Hierarchy), `Ctrl+Alt+L` (Reformat Code), в PyCharm ещё
  `Alt+J/K` у перемещения Jupyter/`#%%`-ячеек (у них остаются `Alt+↑/↓`)

> `Ctrl+Alt+L` в Hyprland раньше блокировал экран, теперь блокировка на
> `Super+Escape` (док 12), иначе сочетание не доходит до IDE.

IDE должна быть **закрыта** при копировании, иначе на выходе перезапишет файл.
IDE хотя бы раз должна быть запущена, чтобы появилась папка конфига. Версию
(`2026.2`) поправь под установленную:

```bash
for ide in PyCharm CLion; do
  d=~/.config/JetBrains/${ide}2026.2
  mkdir -p $d/keymaps $d/options/linux
  cp -v $HOST/configs/jetbrains/${ide,,}-keymap.xml "$d/keymaps/XWin copy.xml"
  [ -f $d/options/linux/keymap.xml ] || cat > $d/options/linux/keymap.xml <<'EOF'
<application>
  <component name="KeymapManager">
    <active_keymap name="XWin copy" />
  </component>
</application>
EOF
done
```

Если `keymap.xml` уже был, выбери раскладку вручную: Settings → Keymap → «XWin copy».
Если `Alt+H` открывает меню Help, выключи Settings → Appearance → «Enable mnemonics in menu».

## Шаг 10 — Claude Code и claude-proxy

> Напрямую Claude Code не работает, поэтому и установка, и работа идут через прокси
> Nekoray на `127.0.0.1:2080` (см. `08 Сеть и синхронизация.md`, Шаг 4). Nekoray должен быть запущен.

Нативный установщик, без sudo и без npm. Ставит `~/.local/bin/claude` → `~/.local/share/claude/versions/<версия>`:

```bash
export https_proxy=http://127.0.0.1:2080
curl -fsSL https://claude.ai/install.sh | bash
unset https_proxy
```

Обёртка `claude-proxy` запускает `claude`, выставив `http(s)_proxy` и `all_proxy` (HTTP и SOCKS5 на одном порту).
Через неё работают и сам агент, и автообновление, и `curl`/`git` из команд, которые агент запускает.
Одна команда создаёт `~/.local/bin/claude-proxy`, делает его исполняемым и добавляет `~/.local/bin` в PATH,
если его там нет. Репо не нужно, скрипт тот же, что `$HOST/configs/claude/claude-proxy.sh`:

```bash
mkdir -p ~/.local/bin
cat > ~/.local/bin/claude-proxy <<'EOF'
#!/bin/sh
set -eu

PROXY_HOST="${PROXY_HOST:-127.0.0.1}"
PROXY_PORT="${PROXY_PORT:-2080}"

CLAUDE_BIN="${CLAUDE_BIN:-claude}"

HTTP_PROXY_URL="http://${PROXY_HOST}:${PROXY_PORT}"
SOCKS_PROXY_URL="socks5://${PROXY_HOST}:${PROXY_PORT}"

if ! command -v "$CLAUDE_BIN" >/dev/null 2>&1; then
    printf 'Ошибка: команда "%s" не найдена.\n' "$CLAUDE_BIN" >&2
    exit 127
fi

exec env \
    http_proxy="$HTTP_PROXY_URL" \
    HTTP_PROXY="$HTTP_PROXY_URL" \
    https_proxy="$HTTP_PROXY_URL" \
    HTTPS_PROXY="$HTTP_PROXY_URL" \
    all_proxy="$SOCKS_PROXY_URL" \
    ALL_PROXY="$SOCKS_PROXY_URL" \
    socks_proxy="$SOCKS_PROXY_URL" \
    SOCKS_PROXY="$SOCKS_PROXY_URL" \
    "$CLAUDE_BIN" "$@"
EOF
chmod 755 ~/.local/bin/claude-proxy
case ":$PATH:" in
    *":$HOME/.local/bin:"*) ;;
    *) echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
       export PATH="$HOME/.local/bin:$PATH" ;;
esac
command -v claude-proxy
```

Из корня репо то же самое короче: `install -Dm755 $HOST/configs/claude/claude-proxy.sh ~/.local/bin/claude-proxy`.

Запуск: `claude-proxy` (аргументы передаются в `claude` как есть, например `claude-proxy --continue`).
Другой прокси задаётся переменными: `PROXY_HOST=… PROXY_PORT=… claude-proxy`. Другой бинарь `claude`
задаётся через `CLAUDE_BIN=…`. При первом запуске войди в аккаунт (`/login`).

Проверка: `claude --version`, затем `claude-proxy` и в нём `/status`.
